# Self-Healing Health Data Pipeline Agent

**Code for a Billion — Bharat Agentic-AI Hackathon 2026**  
**Track: Health**

A self-healing agent that cleans messy public-health and clinical data exports. Every cleaning strategy is generated by an LLM, executed inside a locked-down Docker sandbox, automatically repaired from real errors, validated for basic data quality, and ranked by cost (time × memory). The same sandbox is proven to contain runaway code (infinite loops, resource bombs).

## Problem

Health systems, NGOs, and district hospitals regularly receive messy CSV exports from field apps, labs, and surveys. Columns are misnamed, amounts are strings, duplicates exist, and empty rows break pipelines. Manual cleaning is slow and error-prone. An agent that can propose, test, repair, validate, and select the cheapest safe clean reduces the time from “raw export” to “analysis-ready dataset” from hours to minutes while keeping the host system isolated.

## What the demo shows

1. A planted bad strategy fails with a real `KeyError` (disclosed for demo; not independent discovery).
2. The LLM rewrites the code from the stderr. The repaired version runs successfully in a fresh sandbox.
3. Surviving strategies are ranked by cost **and must pass a validation gate** (unique rows, numeric fields, no blank rows, reasonable row retention). Only validated results can be recommended.
4. An infinite loop is killed by the sandbox while the app stays up (blast-radius zero).
5. The best validated result is available as a downloadable cleaned CSV.

One button does all of this: **Run judge demo**.

## Run locally

```bash
pip install -r requirements.txt
docker build -t data-pipeline-sandbox -f sandbox/Dockerfile sandbox
export VULTR_INFERENCE_API_KEY=your_key   # or any OpenAI-compatible endpoint
streamlit run app.py
```

## Architecture

- **Streamlit UI** — shows sample messy CSV, failure + repair side-by-side, cost + validation table, containment proof, and download button for validated CSV.
- **Agent** — proposes cleaning strategies, executes them in the sandbox, heals failed code from stderr, validates the cleaned DataFrame, ranks by cost.
- **Sandbox runner** — Docker with no network, non-root user, memory/CPU/pids limits, read-only, timeout with explicit container kill, ephemeral containers.
- **LLM** — strategy generation + code repair (any OpenAI-compatible API).

## Limitations (important)

- Sample data is **synthetic only**. Do not use real patient records.
- The first strategy is a **planted failure** for demo purposes so the repair path is visible. It is not evidence of independent problem discovery.
- Validation is basic (uniqueness, numeric coercion, blank rows, row-count sanity). It is not a full clinical reconciliation engine.
- Sandbox isolation is strong for the demonstrated cases but not a formal security audit.
- **AgentFoundry**: Official rules require building inside AgentFoundry. Development evidence must be established by the submitter before the official issue is filed.

## Deploy

Any cloud that can run Docker + Streamlit works. See `deploy.sh` for a simple VM script. Note: when the app itself runs in Docker, the sandbox bind-mount requires a shared host path; test the final architecture.
